# FLM — Feature Local Memory Protocol

> Don't burn your context. FLAME it. 🔥

## Проблема

AI-агенты для разработки (OpenCode, Cursor, Copilot, Claude Code) сжигают токены на повторную загрузку одного и того же контекста. При работе над фичей контекстное окно забивается историей диалога, и агент либо тупеет, либо требует начинать сессию с нуля. Результат: потеря контекста, перерасход токенов, время на восстановление состояния.

## Идея

**FLM (Feature Local Memory)** — это конвенция, а не софт. Протокол управления контекстом через файловую систему проекта, который понимает любой AI-агент.

Агент сам ведёт "оперативную память" в виде маркдаун-файла в ветке фичи, делает саммари при заполнении окна, и восстанавливает состояние в новой сессии простым чтением файла.

Ноль зависимостей. Только `.md` файлы, Git и правильный промпт.

## Как работает

[AGENTS.md]   — постоянная память проекта (архитектура, правила)
[FEATURE.md]  — оперативная память текущей фичи (план, решения, текущий шаг)

### Жизненный цикл

1. **Начало фичи** — агент создаёт `FEATURE.md` в корне ветки, пишет план, затрагиваемые файлы.
2. **Работа** — агент использует `FEATURE.md` как буфер, ссылается на файлы вместо загрузки кода в контекст.
3. **Заполнение окна** (≈70%) — агент сам делает саммари в `FEATURE.md`, сжимая историю до ключевых решений, ошибок и текущего шага.
4. **Новая сессия** — агент читает `AGENTS.md` → находит `FEATURE.md` → восстанавливает контекст.
5. **Завершение** — ключевые решения мигрируют в `AGENTS.md`, `FEATURE.md` удаляется.

## Пример AGENTS.md с FLM-правилами

# Память и контекст (Протокол FLM v0.1)

## Правила оптимизации контекстного окна:
1. При начале работы над фичей создай FEATURE.md в корне ветки.
2. Храни в FEATURE.md: план, архитектурные решения, имена файлов, ошибки и фиксы.
3. Не загружай большие куски кода в контекст — ссылайся на файлы из FEATURE.md.
4. Если история диалога превышает ~70% лимита окна — сделай саммари в FEATURE.md.
5. При старте новой сессии сначала прочитай AGENTS.md, затем FEATURE.md (если есть).
6. При завершении фичи:
   - Перенеси ключевые решения в AGENTS.md в раздел "История решений"
   - Удали FEATURE.md

## Преимущества перед существующими решениями

- **Внешние сервисы памяти (Mem0, LangMem)** — требуют API, базу данных, отдельный сервис. FLM: ноль зависимостей, всё в Git.
- **Саммаризация лога диалога** — сжимает просто историю сообщений. FLM: структурирует память по смыслу (план, решения, ошибки).
- **Статические правила (.cursorrules, AGENTS.md)** — не обновляются агентом. FLM: динамический буфер, агент сам пишет и обновляет FEATURE.md.
- **Проприетарные фичи IDE** — привязаны к конкретному инструменту. FLM: провайдеро-независимый, работает с любым агентом.
